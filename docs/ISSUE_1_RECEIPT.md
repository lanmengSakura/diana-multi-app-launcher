# Issue #1 处理回执 · Beta.4 RC.4

感谢提供详细的环境、耗时与复现记录。最主要的卡顿确实是启动器这边的问题，不是你没有安装 Codex 导致用法不对：之前“未找到”的缓存只有 2 秒，界面却每 2.5 秒重新查询，而且查询占用了界面线程。

本次修正纳入 [v0.1.0-beta.4-rc.4](https://github.com/lanmengSakura/diana-multi-app-launcher/releases/tag/v0.1.0-beta.4-rc.4)，提供安装版、便携版和 SHA-256 校验清单。请先关闭旧启动器，再更新到 RC.4；原来的应用关联保留，不必重装其他应用。

## 已处理

1. **未安装 Codex 时的阻塞查询**：状态查询移到后台，未找到的结果缓存 120 秒，并合并同时发生的查询；AppX 查询最多等待 10 秒。新安装后可以用“关联 → 重新检测”立即刷新。
2. **重复轮询与探测成本**：上一次完成后再安排下一次，隐藏/操作期间暂停；减少不必要的进程信息采集，状态读取不再反复解包 Cursor/Grok 美术，部分被动检查缓存 60 秒。实际挂载仍重新检查，未放宽版本、签名、哈希或授权要求。
3. **重复启动与文件写入**：新增单实例和操作互斥，重复打开只唤回窗口；会话文件写完后再替换，保存失败保留旧记录。
4. **路径与版本排序**：移除作者机器的个人 D 盘候选路径，保留系统目录、已有环境变量/PATH 和手动关联；豆包扩展改按语义版本选择。
5. **便携版构建说明**：补上导出脚本和校验清单。便携版就是 Tauri 构建出的主 EXE，无需另一份程序源码；之前确实没有把导出步骤写清楚。
6. **版本和小窗口说明**：入口明确标注 Cursor `3.17.21`、Grok Bot `0.28.0`、ZCode `3.6.5.4145`。ZCode `3.11.2.6792` 暂不在完整挂载范围，不会强行绕过检查。豆包小视口隐藏立绘/简笔画是现有防遮挡策略，已补充断点与缩放说明。

## 暂未调整

豆包的 `all_frames` 先保留。还需要确认不同宿主页和嵌入页面是否依赖它，不能直接删掉后让某些页面漏挂载；这里没有当作“已验证无问题”。现有美术布局和角色资源也没有改动。

## 测试说明

53 项 Rust 测试、21 项脚本测试，以及 TypeScript/生产构建和资源哈希检查通过。自动化使用假查询、假时钟和独立临时目录，没有操作正在使用的目标应用。

尚未在你报告的 Windows 10 / 8GB 环境复验，也没有重跑八款应用的真实挂载、恢复和干净机器安装测试，所以不把“代码和测试通过”等同于你的机器已经完全恢复正常。方便时可以先试 RC.4；如果仍卡顿，请补充选中的应用、是否已最小化、卡住前的操作和脱敏错误码，不需要上传私人路径、会话正文或整份状态文件。

完整调试连接仍由用户知情选择：回环端口没有身份认证，同机进程可能读取界面或执行渲染脚本；撤下皮肤或关闭启动器不等于关闭目标应用持有的端口，须完整退出该目标应用。说明见 [SECURITY.md](../SECURITY.md)。

构建产物、校验值与具体检查范围见 [交付检查记录](RELEASE_RC4_VALIDATION.md)。这份回执随版本提供；Issue 保持开放，便于后续反馈。
