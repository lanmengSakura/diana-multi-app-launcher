# Diana 多合一启动器 · Beta.4 RC.9

Windows x64 预发布修复版，提供安装包、便携 EXE 和 SHA-256 摘要。请手动下载更新；RC.8 文件保留可回退，不覆盖旧发布。

## 修复内容

- **ZCode 本机适配登记**：改用明确的本机路径解析，区分目录环境异常、登记缺失、读取失败、格式/版本不符。无效登记不再显示“已就绪”，也不会作为缺少登记而绕过校验。
- **Cursor 适配器状态**：补齐与 Grok Bot 一致的文件校验状态检测，损坏的清单或资源不再只凭路径就显示就绪。
- **Cursor / Grok Bot 重新检测**：主动重新检测、保存关联及执行动作会清除适配校验缓存，避免文件修好后仍沿用旧失败结果。异常时提供“重新校验并挂载”，保留逐次风险确认及操作前的完整校验；只从内置审核资源修复受管文件，不重写外部适配器、会话或恢复记录。
- **DeepSeek 桌面端配置识别**：支持 Windows 常见的 UTF-8 BOM，与官方插件管理脚本的读取方式一致；安装依赖与启用状态必须同时满足，不再把无效依赖误报成已部署。

本次不改立绘、按钮尺寸、动画和内置《Hopeful Dreamer》配乐，不改 DeepSeek 桌面/网页入口分工，也不放开未知应用版本或签名。

## ZCode 新版支持范围

**这是登记读取修复，不是 ZCode 3.16 的通用一键适配发行版。** 公开包仍内置 `3.6.5.4145` 适配器；`3.16.3.8992` 只有已经单独制作、批准并登记本机适配器的环境才能使用对应入口。私有适配脚本、个人路径、账号和登录态未打包或提交。

此前单机原生启动器的登记识别已恢复，随后用户手动挂载，启动器回报成功。这不等于已经在所有机器复现或完成全部场景验收，也不能据此把一个路径分隔符认定为唯一根因。

- 便携版：`diana-multi-app-launcher_0.1.0-beta.4-rc.9_x64-portable.exe`
- 文件摘要：`SHA256SUMS.txt`

正常退出旧启动器后更新；无需重装目标应用、清空登录态或删除关联配置。EXE 未签名，只从本仓库 Release 下载并核对摘要。需要回退时正常退出启动器，再使用保留的旧版程序。

Codex、Cursor、Grok Bot 与 ZCode 的实验挂载仍在用户确认后才开启临时调试会话。回环端口不是身份认证，同机进程仍可能读取界面、执行渲染脚本或截图；关闭启动器或撤下美术不等于关闭端口，须完整退出持有端口的目标应用。详见 [风险与退出说明](https://github.com/lanmengSakura/diana-multi-app-launcher/blob/main/SECURITY.md)。
